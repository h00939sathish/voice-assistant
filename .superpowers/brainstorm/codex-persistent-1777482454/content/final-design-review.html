Final design review: AionUi pet companion for Jarvis

Approve this as the spec direction before it gets written into the project docs.

Core decision
AionUi pet
mascot + click-to-talk
→
Jarvis
existing voice brain

The pet sends a wake trigger. Jarvis still owns microphone capture, VAD, STT, LLM routing, tools, memory, safety gates, TTS, and follow-up listening.

API surface

POST /api/companion/wake triggers listening. GET /api/companion/state returns current state. WS/SSE events stream state updates to the pet.

Pet states

IDLE → idle, LISTENING → attentive, PROCESSING → thinking, SPEAKING → talking, confirmation → bubble, error → error, completed → done then idle.

Safety behavior

If Jarvis is busy, wake returns accepted:false with the current state. Tool confirmations remain inside Jarvis safety gates and can be mirrored to the pet.

Testing

Unit tests cover wake endpoint behavior, busy-state rejection, state feed payloads, and confirmation/error event mapping. No AionUi audio upload in this first slice.
